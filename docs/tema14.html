Python en Jupyter Notebook: reactivación y diseño de programas

Cómo recuperar Python programando desde el primer momento y convertir un problema pequeño en funciones claras, comprobables y documentadas.

Pregunta guía

¿Cómo pasamos de entender un problema a construir en un Jupyter Notebook un programa que podamos ejecutar, comprobar y mejorar por partes?

Este tema no repite variables, decisiones, bucles y funciones como unidades aisladas: los reactiva al construir programas pequeños y completos. El objetivo es elaborar soluciones sencillas, estructuradas y verificables, de acuerdo con los saberes de programación del currículo.[61]

Antes de empezar: un programa no queda bien diseñado solo porque «funcione una vez». También debe dejar claro qué datos recibe, qué resultado produce, cómo se divide y con qué casos se ha comprobado.
Al terminar serás capaz de…
  • trabajar con celdas de código y texto sin perder de vista el estado de la sesión;
  • integrar variables, tipos, operadores, entrada y salida en programas breves;
  • usar condicionales y bucles para expresar reglas y recorridos;
  • definir funciones con parámetros y valores de retorno;
  • distinguir variables locales y globales y separar cálculo, entrada y presentación;
  • reutilizar la biblioteca estándar y escribir docstrings básicos;
  • planificar con ejemplos, entradas, salidas, casos de prueba y funciones;
  • desarrollar de forma incremental con nombres claros y funciones breves.

1. Jupyter Notebook: qué es un Notebook, celdas, ejecución y estado de la sesión

Un Notebook —o cuaderno computacional— es un documento que combina celdas de texto, útiles para explicar decisiones, y celdas de código, que se envían a un entorno de ejecución. En el ecosistema Jupyter, Jupyter Notebook puede referirse tanto a la aplicación web clásica como, de forma habitual, a un documento guardado en formato .ipynb.[69]

En la asignatura trabajaremos mayoritariamente con Google Colab, un servicio alojado de Jupyter Notebooks que permite escribir y ejecutar Python desde el navegador sin instalar el entorno en el equipo. El Notebook puede guardarse en Google Drive o cargarse desde otras fuentes compatibles.[62]

Notebook: el documento

Conserva texto, código y resultados guardados. Organiza una explicación en una secuencia legible y puede volver a abrirse más tarde.

Sesión: la ejecución viva

Mantiene temporalmente variables, funciones importadas o definidas y archivos de la máquina virtual. Ese estado puede desaparecer al reiniciar o desconectar el entorno.

Las celdas pueden ejecutarse en cualquier orden. Por eso el orden visual del Notebook y el orden real de ejecución no siempre coinciden. Si una celda usa precio, funcionará únicamente si antes se ejecutó otra que asignó ese nombre en la sesión actual.

# Celda 1
precio = 12.50
unidades = 4

# Celda 2, ejecutada después de la anterior
total = precio * unidades
print(f"Total: {total:.2f} €")
# Salida: Total: 50.00 €

Si se cambia precio en la primera celda pero no se vuelve a ejecutar, la segunda conserva el valor anterior de la sesión. Los números que Colab muestra junto a las celdas ayudan a reconocer el orden de ejecución, pero la comprobación más fiable es reiniciar y ejecutar todo desde el principio. Un Notebook reproducible no debe depender de una acción olvidada.

1 — Leer

Revisar la explicación y las entradas esperadas antes de ejecutar.

2 — Ejecutar en orden

Empezar arriba y avanzar hacia abajo cuando las celdas dependen unas de otras.

3 — Interpretar la salida

Distinguir entre el valor mostrado, un mensaje producido por print y un error con su traza.

4 — Reiniciar y comprobar

Ejecutar todo en una sesión limpia para confirmar que el Notebook contiene realmente lo necesario.

El Notebook no es la máquina virtualColab ejecuta el código en una máquina virtual privada para la cuenta, pero esas máquinas se eliminan tras un periodo de inactividad y tienen una duración máxima. Las variables y los archivos temporales no deben confundirse con el contenido guardado del Notebook.[63]

2. Repaso aplicado de variables, tipos, operadores, entrada y salida

Una variable vincula un nombre con un valor. El tipo del valor determina qué operaciones tienen sentido: se pueden sumar números, concatenar textos o combinar condiciones booleanas, pero no sumar directamente una cadena y un entero. Python incluye funciones como input, print, int, float, str y round, disponibles sin importar ninguna biblioteca.[64]

La reactivación resulta más útil dentro de una situación completa. Este programa recibe una distancia y un consumo medio, calcula los litros previstos y presenta el resultado:

distancia_km = float(input("Distancia del viaje (km): "))
consumo_100_km = float(input("Consumo (L/100 km): "))

litros = distancia_km * consumo_100_km / 100
print(f"Combustible previsto: {litros:.2f} L")

# Con 250 y 6.4, la salida es:
# Combustible previsto: 16.00 L
Lectura del programa de consumo
ElementoEjemploPapel que cumple
Entrada250 y 6.4Datos que cambian entre ejecuciones.
Conversiónfloat(...)Transforma el texto devuelto por input en un número decimal.
Cálculodistancia_km * consumo_100_km / 100Aplica operadores a los datos.
Salida16.00 LPresenta el resultado con una unidad y dos decimales.

Los nombres incluyen la unidad porque distancia sería ambiguo. La expresión calcula con toda la precisión disponible y el formato :.2f limita solo la presentación. Redondear después de cada operación puede acumular diferencias innecesarias.

Entrada no equivale a dato válido. float convierte un texto numérico, pero una distancia negativa sigue siendo numéricamente válida para Python y conceptualmente incorrecta para este problema. La validación sistemática de errores se desarrollará en el Tema 17.

3. Condicionales y bucles dentro de pequeños programas completos

Una estructura de control responde a una necesidad del problema. Un if selecciona una ruta según una condición; un for recorre elementos; un while repite mientras se mantenga una condición. La indentación define qué instrucciones pertenecen a cada bloque.[65]

El siguiente programa recorre temperaturas ya registradas, cuenta cuántas superan el umbral y clasifica el resultado. La lista permite ver el programa completo sin convertir esta sección en un manual de colecciones, que se estudiarán en el Tema 15.

temperaturas = [18.5, 21.0, 23.5, 19.0]
umbral = 20.0
dias_calidos = 0

for temperatura in temperaturas:
    if temperatura > umbral:
        dias_calidos += 1

if dias_calidos == 0:
    mensaje = "Ningún registro supera el umbral"
elif dias_calidos == 1:
    mensaje = "Un registro supera el umbral"
else:
    mensaje = f"{dias_calidos} registros superan el umbral"

print(mensaje)
# Salida: 2 registros superan el umbral

La decisión

temperatura > umbral produce True o False. Solo cuando es verdadera aumenta el contador.

El recorrido

El for aplica la misma regla a cada temperatura y termina al agotar la secuencia.

El estado

dias_calidos resume lo observado hasta ese momento y cambia durante el recorrido.

La presentación

El segundo condicional adapta el texto a cero, uno o varios registros.

Un while es preferible cuando no se sabe de antemano cuántas repeticiones harán falta, por ejemplo al solicitar una entrada hasta que cumpla una condición. Debe existir alguna operación que acerque el bucle a su final; de lo contrario puede no terminar.

No elijas primero la palabra de PythonPregunta primero si el problema necesita escoger, recorrer o repetir hasta que ocurra algo. Después elige if, for o while. La estructura expresa la lógica; no es un adorno sintáctico.

4. Funciones, parámetros, argumentos y valores de retorno

Una función reúne instrucciones bajo un nombre y permite ejecutarlas cuando se necesiten. En la definición, los parámetros nombran los datos que recibirá; en una llamada, los argumentos son los valores concretos enviados. return termina la llamada y devuelve un resultado al punto desde el que se invocó.[65]

def coste_viaje(distancia_km, consumo_100_km, precio_litro):
    litros = distancia_km * consumo_100_km / 100
    return litros * precio_litro

coste = coste_viaje(250, 6.4, 1.62)
print(f"Coste previsto: {coste:.2f} €")
# Salida: Coste previsto: 25.92 €
Definición y llamada de la función
ConceptoEn el fragmentoSignificado
Nombrecoste_viajeExpresa la operación que realiza la función.
Parámetrosdistancia_km, consumo_100_km, precio_litroNombres locales que recibirán datos en cada llamada.
Argumentos250, 6.4, 1.62Valores usados en esta llamada concreta.
Retornolitros * precio_litroValor calculado que puede guardarse, comparar o presentar.

print y return no son equivalentes. print muestra texto y devuelve None; return entrega un valor al resto del programa. Si la función solo imprimiera el coste, resultaría más difícil compararlo con un presupuesto, redondearlo para otro uso o comprobarlo mediante pruebas.

Analogía: una función se parece a una máquina con una entrada y una salida. Los parámetros describen las conexiones disponibles; los argumentos son lo que se introduce en una ejecución; el valor de retorno es el producto que puede utilizar otra parte del programa.

5. Alcance de las variables y separación entre cálculo, entrada y presentación

El alcance indica la región del programa donde un nombre puede utilizarse directamente. Los parámetros y nombres asignados dentro de una función son normalmente locales: se crean para esa llamada. Los nombres definidos en el nivel principal del Notebook son globales para las funciones allí definidas, aunque depender de ellos sin necesidad oculta las entradas reales de una función.[66]

iva = 0.21

def precio_final(precio_base, tipo_iva):
    impuesto = precio_base * tipo_iva
    return precio_base + impuesto

resultado = precio_final(80, iva)
print(f"Precio final: {resultado:.2f} €")
# Salida: Precio final: 96.80 €
# Fuera de la función, 'impuesto' no está definido.

La función recibe tipo_iva de forma explícita. Así puede comprobarse con diferentes tipos y no depende secretamente de que exista una variable global llamada iva. impuesto es un detalle local del cálculo y deja de estar disponible cuando termina la llamada.

Tres responsabilidades distintas

Entrada

Obtiene datos mediante input, una celda o una fuente externa. Su responsabilidad es recogerlos y, cuando proceda, convertirlos.

Cálculo

Recibe valores, aplica reglas y retorna resultados. Evita preguntar o imprimir si esas acciones no forman parte del cálculo.

Presentación

Transforma resultados en mensajes comprensibles, con etiquetas, unidades y formato adecuado.

def calcular_media(nota_1, nota_2):
    return (nota_1 + nota_2) / 2

primera = float(input("Primera nota: "))
segunda = float(input("Segunda nota: "))
media = calcular_media(primera, segunda)
print(f"Media: {media:.1f}")
Evita modificar globales desde una funciónPuede hacerse con global, pero en programas sencillos suele aumentar el acoplamiento y esconder cambios de estado. Recibir los datos como parámetros y devolver el resultado hace visible el recorrido de la información.

6. Biblioteca estándar, reutilización de funciones y docstrings básicos

Python incorpora una biblioteca estándar con módulos preparados para tareas frecuentes. import permite reutilizarlos sin copiar su implementación. En este tema se usan módulos existentes dentro de un solo Notebook; todavía no se crean módulos propios ni programas distribuidos en varios archivos.[67]

import math


def longitud_circunferencia(radio):
    """Devuelve la longitud de una circunferencia dado su radio."""
    return 2 * math.pi * radio

longitud = longitud_circunferencia(3)
print(f"Longitud: {longitud:.2f}")
# Salida: Longitud: 18.85

math.pi reutiliza una constante del módulo math. Escribir el prefijo math. deja clara su procedencia. Otros módulos estándar apropiados para programas breves son statistics para cálculos estadísticos sencillos, datetime para fechas y horas y random para selecciones pseudoaleatorias. La documentación de random advierte que sus generadores no deben usarse con fines de seguridad.[68]

Reutilizar no es copiar y pegarUna llamada a una función —propia, incorporada o importada— expresa qué servicio se necesita. Copiar el mismo cálculo en varios lugares crea versiones que pueden separarse cuando haya que corregirlo.

Documentación mínima de una función

Un docstring es una cadena situada como primera instrucción del cuerpo de una función. Su primera línea debe resumir qué hace la función. En funciones sencillas puede bastar una frase; si los parámetros, el retorno o las condiciones no son evidentes, se añaden de forma breve.[65]

def convertir_minutos(minutos):
    """Convierte una duración entera en horas y minutos.

    Devuelve una tupla (horas, minutos_restantes).
    """
    return divmod(minutos, 60)

print(convertir_minutos(135))
# Salida: (2, 15)

El docstring explica el contrato; no repite línea por línea el código. Puede consultarse con help(convertir_minutos) o mediante convertir_minutos.__doc__. Los comentarios, en cambio, aclaran decisiones internas concretas cuando el código por sí solo no basta.

7. Planificación directa con ejemplos, casos de prueba y descomposición en tareas

Planificar no exige traducir el programa a otro lenguaje. Puede hacerse directamente con una descripción breve del objetivo, ejemplos de entrada y salida, casos de prueba y una división en funciones. Esta representación conecta la intención con código Python ejecutable.

Problema de referencia: dado un importe y un porcentaje de descuento, calcular el precio final. Si el descuento queda fuera del intervalo de 0 a 100, no se puede obtener un resultado válido.
Planificación mediante ejemplos y casos de prueba
CasoEntrada: importe, descuentoSalida esperadaQué comprueba
Normal80, 2560.0Aplica un descuento habitual.
Sin descuento80, 080.0Comprueba el límite inferior.
Descuento total80, 1000.0Comprueba el límite superior.
No válido80, 120NoneRechaza un porcentaje fuera del intervalo.

Descomposición antes del código

  1. Calcular: una función recibe importe y porcentaje, valida el intervalo y retorna el precio o None.
  2. Recoger: el nivel principal obtiene y convierte las dos entradas.
  3. Presentar: el nivel principal distingue entre resultado válido y dato rechazado.
  4. Comprobar: las llamadas de prueba comparan el resultado real con el esperado.
def aplicar_descuento(importe, porcentaje):
    """Devuelve el precio final o None si el porcentaje no es válido."""
    if not 0 <= porcentaje <= 100:
        return None
    return importe * (1 - porcentaje / 100)

assert aplicar_descuento(80, 25) == 60.0
assert aplicar_descuento(80, 0) == 80.0
assert aplicar_descuento(80, 100) == 0.0
assert aplicar_descuento(80, 120) is None

Las cuatro aserciones no producen salida cuando se cumplen; si una comparación es falsa, Python detiene esa ejecución con AssertionError. Aquí sirven para hacer visibles las expectativas durante el diseño. Las técnicas de prueba y el tratamiento sistemático de entradas no válidas se ampliarán en el Tema 17.

Un caso de prueba es una afirmación concreta: «con estas entradas espero esta salida». No se limita a ejecutar y mirar; permite detectar si una modificación rompe un comportamiento que ya estaba decidido.

8. Desarrollo incremental, nombres claros y funciones breves

El desarrollo incremental construye una solución en pasos pequeños que se ejecutan y comprueban. No consiste en escribir todo el programa y depurarlo al final, sino en conservar una versión que funciona mientras se añade una sola decisión cada vez.

Incremento 1 — Un cálculo conocido

Escribir la expresión para un ejemplo concreto y confirmar a mano el resultado: 80 * (1 - 25 / 100) produce 60.0.

Incremento 2 — Una función

Encapsular el cálculo en aplicar_descuento(importe, porcentaje) y repetir el caso conocido.

Incremento 3 — Límites

Añadir la regla de 0 a 100 y comprobar casos normales, límites y un valor no válido.

Incremento 4 — Interacción

Incorporar input y presentación solo después de comprobar el cálculo aislado.

Incremento 5 — Revisión limpia

Reiniciar la sesión del Notebook, ejecutar todas las celdas en orden y confirmar los resultados.

«Breve» no significa un número obligatorio de líneas. Una función tiene una longitud adecuada cuando su finalidad se puede nombrar con precisión, sus entradas y salida son reconocibles y no mezcla responsabilidades sin relación. Dividir demasiado también perjudica: una función diminuta que solo oculta una operación evidente puede obligar a saltar continuamente por el Notebook.

Ciclo de trabajoEjemplo conocido → fragmento mínimo → ejecución → comparación con lo esperado → siguiente incremento → ejecución completa desde una sesión limpia. Cada paso reduce la distancia entre el fallo y la causa que lo introdujo.

Glosario del tema

Notebook
Cuaderno computacional que combina celdas de texto, código ejecutable y resultados; suele guardarse como archivo .ipynb.
Entorno de ejecución
Sistema que ejecuta el código y mantiene temporalmente el estado de la sesión.
Estado
Conjunto de valores, definiciones y recursos disponibles en un momento de la ejecución.
Variable
Nombre vinculado a un valor durante la ejecución de un programa.
Tipo
Categoría de un valor que determina sus operaciones y comportamiento.
Condición
Expresión cuyo resultado se interpreta como verdadero o falso.
Iteración
Cada repetición de las instrucciones de un bucle.
Función
Bloque de código con nombre que puede recibir datos y devolver un resultado.
Parámetro
Nombre declarado por una función para recibir un dato.
Argumento
Valor concreto proporcionado en una llamada a una función.
Valor de retorno
Resultado que una función entrega mediante return.
Alcance
Región del programa desde la que un nombre es accesible directamente.
Biblioteca estándar
Conjunto de módulos distribuidos con Python para resolver tareas comunes.
Docstring
Cadena inicial de una función, clase o módulo que documenta su finalidad.
Caso de prueba
Entradas concretas asociadas a un resultado o comportamiento esperado.
Desarrollo incremental
Construcción y comprobación de un programa mediante cambios pequeños sucesivos.

Resumen esencial

  1. Jupyter Notebook combina un documento .ipynb guardable con una sesión que mantiene el estado de ejecución; en clase utilizaremos principalmente Google Colab para trabajar con estos Notebooks.
  2. Ejecutar celdas fuera de orden puede dejar un estado engañoso; reiniciar y ejecutar todo comprueba la reproducibilidad.
  3. Variables, tipos, operadores, entrada y salida adquieren sentido dentro de un programa con datos y unidades claros.
  4. Los condicionales seleccionan rutas; los bucles recorren o repiten; ambos expresan necesidades del problema.
  5. Los parámetros describen entradas de una función, los argumentos aportan valores y return entrega el resultado.
  6. Las variables locales aíslan detalles; separar entrada, cálculo y presentación reduce dependencias.
  7. La biblioteca estándar reutiliza soluciones existentes; un docstring básico explica el contrato de una función.
  8. Ejemplos, entradas, salidas, casos de prueba y funciones permiten planificar directamente sin pseudocódigo.
  9. El desarrollo incremental añade una decisión cada vez y vuelve a ejecutar las comprobaciones.
  10. Nombres claros y funciones breves hacen visible la intención, pero dividir sin propósito también dificulta la lectura.
