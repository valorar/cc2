Un dato aislado cabe en una variable; un conjunto de observaciones necesita estructura. Python aporta colecciones para representar esos datos y módulos de su biblioteca estándar para leerlos y escribirlos. El objetivo no es memorizar métodos, sino construir un recorrido coherente: representar, procesar, validar y conservar. Este contenido desarrolla el almacenamiento y la lectura y escritura de datos previstos en el currículo.[70]

Idea de partida: una colección organiza datos dentro del programa; un fichero permite recuperarlos después o intercambiarlos con otro programa. Elegir bien ambas representaciones evita conversiones innecesarias y errores difíciles de detectar.

  • organizar un flujo de carga, validación, transformación y exportación.

1. Listas, tuplas, diccionarios y conjuntos

Una colección reúne varios valores bajo una sola variable. Las colecciones integradas de Python resuelven necesidades diferentes: mantener una secuencia, fijar un registro inmutable, asociar claves con valores o conservar elementos sin duplicados. La documentación oficial reúne sus operaciones esenciales y advierte, por ejemplo, que {} crea un diccionario vacío y no un conjunto vacío.[71]

Comparación de las cuatro colecciones básicas
ColecciónPropiedad principalAccesoEjemplo
ListaSecuencia ordenada y mutable; admite repetidos.Por índice, desde 0, y mediante cortes.["Ana", "Leo", "Ana"]
TuplaSecuencia ordenada e inmutable; admite repetidos.Por índice y mediante desempaquetado.(40.4, -3.7)
DiccionarioAsocia claves únicas con valores y conserva el orden de inserción.Por clave, no por posición numérica.{"nombre": "Ana", "nota": 8.5}
ConjuntoElementos únicos, sin acceso posicional.Por pertenencia y operaciones de conjuntos.{"python", "datos"}

Listas: secuencias que cambian

Una lista resulta adecuada cuando importa el orden y habrá que añadir, eliminar o sustituir elementos. append añade uno al final; extend incorpora varios; insert coloca en una posición; remove elimina la primera coincidencia y pop extrae un elemento. Los índices negativos cuentan desde el final y un corte como notas[1:4] obtiene una nueva lista con las posiciones 1, 2 y 3.

notas = [7.5, 6.0, 9.0]
notas.append(8.5)
notas[1] = 6.5
primera, ultima = notas[0], notas[-1]

Asignar una lista a otra variable no la copia: ambas variables apuntan al mismo objeto. Si hace falta una copia superficial independiente puede usarse notas.copy() o notas[:]. «Superficial» significa que las colecciones anidadas interiores todavía pueden ser compartidas.

Tuplas: una secuencia que no se modifica

Una tupla agrupa valores cuyo número y significado se mantienen, como una coordenada o el resultado múltiple de una función. Es inmutable: no se puede sustituir punto[0], aunque un objeto mutable guardado dentro sí podría cambiar. En una tupla de un único elemento la coma es imprescindible: (5,).

punto = (40.4168, -3.7038)
latitud, longitud = punto

Diccionarios: valores identificados por claves

Un diccionario modela propiedades con nombre. Cada clave es única y debe ser hashable: su valor hash debe permanecer estable, como ocurre con cadenas, números o tuplas formadas por elementos hashables. La expresión alumno["nota"] exige que exista la clave; alumno.get("nota") devuelve None —o el valor alternativo indicado— si falta. Esta diferencia permite decidir si una ausencia es un error o una situación esperada.

alumno = {"nombre": "Ana", "nota": 8.5}
alumno["grupo"] = "2B"
nota = alumno.get("nota", 0)

Conjuntos: unicidad y pertenencia

Un conjunto elimina duplicados y hace explícitas operaciones como unión (|), intersección (&) y diferencia (-). No debe utilizarse cuando sea necesario conservar posiciones o repeticiones. Para crear uno vacío se escribe set().

etiquetas = {"python", "datos", "python"}
obligatorias = {"python", "json"}
comunes = etiquetas & obligatorias  # {"python"}
La sintaxis revela el modeloventas[2] pide el tercer elemento de una secuencia; venta["precio"] pide una propiedad por su nombre; "python" in etiquetas pregunta por pertenencia. La colección elegida comunica cómo deben interpretarse los datos.

2. Acceso, modificación, recorrido, búsqueda, ordenación, filtrado y agregación

Procesar una colección consiste en obtener información o producir una representación nueva. Conviene distinguir las operaciones que modifican el objeto original de las que devuelven otro valor. Por ejemplo, lista.sort() ordena la lista en el sitio y devuelve None, mientras que sorted(iterable) devuelve una lista nueva y acepta cualquier iterable.[72]

Operaciones habituales sobre colecciones
OperaciónPregunta que respondeRecursos de Python
Acceso¿Qué valor ocupa esta posición o corresponde a esta clave?Índices, cortes, claves, get.
Modificación¿Cómo añado, sustituyo o retiro un valor?Asignación, append, update, add, remove.
Recorrido¿Cómo trato cada elemento?for, enumerate, dict.items().
Búsqueda¿Existe el dato y, si procede, dónde?in, index, get.
Ordenación¿En qué secuencia quiero presentar los datos?sorted, list.sort, parámetros key y reverse.
Filtrado¿Qué elementos cumplen una condición?Bucle con condición o comprensión.
Agregación¿Qué resumen produce toda la colección?len, sum, min, max, contador o acumulador.

Recorrer con la información necesaria

temperaturas = [18.2, 21.0, 19.5]
for posicion, valor in enumerate(temperaturas):
    print(posicion, valor)

alumno = {"nombre": "Ana", "nota": 8.5}
for clave, valor in alumno.items():
    print(clave, valor)

Recorrer directamente los elementos suele ser más claro que recorrer índices. El índice tiene sentido si también se necesita la posición; en diccionarios, items() entrega a la vez clave y valor. No conviene añadir o retirar elementos de una colección mientras se recorre esa misma colección, porque se pueden omitir datos o provocar errores.

Buscar sin confundir existencia y posición

El operador in devuelve un booleano. En una lista o tupla comprueba valores; en un conjunto, elementos; en un diccionario, claves. list.index(valor) devuelve la primera posición, pero genera una excepción si no existe. Cuando solo hace falta saber si está, in expresa mejor la intención.

if "nota" in alumno:
    print(alumno["nota"])

contiene_aprobado = any(nota >= 5 for nota in temperaturas)

Ordenar por un criterio explícito

Una ordenación no cambia el significado de un registro; cambia su posición en la secuencia resultante. El parámetro key calcula para cada elemento la clave usada al comparar. Así se pueden ordenar diccionarios por una propiedad sin perder su estructura.

alumnos = [
    {"nombre": "Leo", "nota": 7.0},
    {"nombre": "Ana", "nota": 8.5},
]
por_nota = sorted(alumnos, key=lambda a: a["nota"], reverse=True)

Filtrar, transformar y agregar

Filtrar conserva los elementos que cumplen una condición; transformar calcula una nueva representación; agregar reduce varios datos a un resumen. Una comprensión de listas combina de forma breve transformación y filtrado. Es una técnica útil cuando la expresión sigue siendo legible, no un objetivo separado ni una obligación.

notas = [7.0, 4.5, 8.5, 6.0]
aprobadas = [nota for nota in notas if nota >= 5]
porcentajes = [nota * 10 for nota in aprobadas]
media = sum(notas) / len(notas) if notas else None

La condición final evita dividir entre cero cuando no hay datos. Una agregación correcta debe definir qué ocurre ante una colección vacía y qué datos se excluyen. min([]) y max([]), por ejemplo, no tienen resultado y generan una excepción si no se proporciona un valor por defecto.

Criterio de claridad: una operación breve puede expresarse con una comprensión; cuando hay varias condiciones, conversiones o decisiones, un bucle explícito suele ser más fácil de leer, explicar y depurar.

3. Estructuras anidadas sencillas para representar registros

Una colección puede contener otras colecciones. Una lista de diccionarios representa bien una tabla sencilla: la lista reúne filas y cada diccionario identifica los campos de una fila. También puede haber listas dentro de cada registro, por ejemplo para guardar etiquetas.

registros = [
    {"nombre": "Ana", "notas": [7.5, 8.0], "activo": True},
    {"nombre": "Leo", "notas": [6.0, 7.0], "activo": False},
]

primera_nota = registros[0]["notas"][0]

La lectura se hace de fuera hacia dentro: registros[0] obtiene el primer diccionario; ["notas"], su lista de notas; y el último [0], la primera nota. Una expresión demasiado encadenada puede ocultar dónde falta un dato, por lo que es razonable separar pasos y usar nombres intermedios.

Estructura uniforme

Los registros comparables deberían utilizar las mismas claves y tipos. Si nota es un número en una fila y texto en otra, ordenar o calcular una media puede fallar.

Ausencia explícita

Un campo opcional puede omitirse o usar None, pero el programa debe adoptar un criterio estable y distinguir «desconocido» de cero o cadena vacía.

Profundidad limitada

Demasiados niveles dificultan acceso y validación. Para un problema sencillo conviene una estructura sencilla, con cada nivel justificado.

Al copiar estructuras anidadas hay que recordar la diferencia entre copia superficial y profunda. registros.copy() crea otra lista exterior, pero sus diccionarios interiores siguen siendo los mismos objetos. Modificar uno de ellos se observará desde ambas listas. Cuando se necesiten objetos interiores independientes puede usarse copy.deepcopy, aunque antes conviene comprobar si el diseño necesita realmente duplicar toda la estructura.

Los datos externos no heredan el esquema imaginadoQue el programa espere una lista de registros con nombre y nota no garantiza que el fichero los contenga. La forma y los tipos deben validarse al cargar, antes de ordenar, calcular o exportar.

4. Elección de la colección adecuada para cada problema

No hay una colección «mejor» en términos absolutos. La elección depende de las invariantes del problema: si importa el orden, si se permiten duplicados, si habrá cambios, si el acceso se hace por posición o por nombre y qué operaciones serán frecuentes.

Decidir a partir de la necesidad
Necesidad dominanteElección inicialRazón
Secuencia editable de medicionesListaConserva orden, repetidos y permite añadir o sustituir.
Coordenada formada por dos valores que no deben cambiarTuplaSu tamaño y orden forman una unidad estable.
Ficha con campos identificados por nombreDiccionarioLas claves describen cada propiedad y evitan depender de posiciones opacas.
Etiquetas únicas o comparación de pertenenciaConjuntoElimina duplicados y ofrece unión, intersección y diferencia.
Varias fichas en un orden determinadoLista de diccionariosCombina una secuencia exterior con registros de campos nombrados.
Localizar rápidamente una ficha por identificadorDiccionario de diccionariosEl identificador funciona como clave de acceso directo.

Preguntas antes de decidir

  1. ¿Importa el orden? Si hay primera, siguiente o última posición, se necesita una secuencia; si solo importa pertenencia, puede bastar un conjunto.
  2. ¿Se permiten duplicados? Un conjunto los elimina; una lista o tupla los conserva.
  3. ¿Cambiará la colección? Lista, diccionario y conjunto son mutables; la tupla no.
  4. ¿Cómo se identifica cada dato? Una posición favorece lista o tupla; una clave con significado favorece diccionario.
  5. ¿Qué debe exportarse? JSON representa de forma natural listas y diccionarios; un conjunto o una tupla puede requerir conversión y perder parte de su significado.

La eficiencia importa cuando crece el volumen, pero en programas pequeños la claridad del modelo suele ser el primer criterio. Elegir un conjunto solo porque la búsqueda de pertenencia suele ser rápida sería incorrecto si deben conservarse repeticiones y posiciones.

Representar una reglaLa estructura puede hacer visible una regla del dominio: una tupla comunica estabilidad, un conjunto comunica unicidad y un diccionario comunica campos nombrados. Si la estructura contradice el problema, el código necesitará correcciones continuas.

5. Lectura y escritura de ficheros con gestores de contexto

Las variables viven en la memoria del proceso. Un fichero permite guardar datos fuera de ese proceso o recibirlos de otra aplicación. open abre un recurso y devuelve un objeto fichero; el gestor de contexto with garantiza su cierre al abandonar el bloque, incluso si se produce una excepción. Es la forma recomendada por el tutorial oficial de Python.[73]

with open("saludo.txt", "w", encoding="utf-8") as fichero:
    fichero.write("Hola, datos\n")

with open("saludo.txt", "r", encoding="utf-8") as fichero:
    contenido = fichero.read()

La indentación delimita el tiempo durante el que el fichero está abierto. Fuera del bloque se conserva el texto leído en contenido, pero ya no debe intentarse leer o escribir mediante fichero.

Modos de apertura habituales
ModoComportamientoPrecaución
"r"Lee; es el modo predeterminado.El fichero debe existir.
"w"Escribe desde el principio.Trunca el contenido anterior si el fichero existe.
"a"Añade al final.No sustituye ni corrige líneas ya guardadas.
"x"Crea un fichero nuevo.Falla si ya existe, lo que evita sobrescribirlo por accidente.
"b"Trabaja en binario, combinado como "rb" o "wb".Lee y escribe bytes, no cadenas de texto.

Leer todo o procesar línea a línea

read() carga el contenido completo y es cómodo para ficheros pequeños. Recorrer el fichero procesa una línea cada vez y evita almacenar todo de golpe. Cada línea puede conservar el salto final; rstrip("\n") retira específicamente ese salto sin borrar otros espacios significativos.

with open("nombres.txt", encoding="utf-8") as fichero:
    for linea in fichero:
        nombre = linea.rstrip("\n")
        print(nombre)

write no añade saltos de línea automáticamente. writelines tampoco: escribe las cadenas tal como se reciben. El programa debe decidir de manera explícita cómo separar los registros.

Abrir en escritura puede destruir datosEl modo "w" vacía un fichero existente en el momento de abrirlo. Antes de exportar conviene construir una ruta de salida distinta, comprobar si debe reemplazarse y conservar el original cuando los datos sean importantes.

6. Formatos de texto, CSV y JSON

Un formato define cómo se representan los datos dentro del fichero. Elegirlo exige pensar en estructura, destinatario y compatibilidad. Cambiar la extensión no convierte el contenido: para pasar de CSV a JSON hay que leer la estructura de origen y serializarla con las reglas del formato de destino.

Tres formas de conservar o intercambiar datos
FormatoEstructuraVentajaLímite
Texto planoCaracteres y líneas definidos por el programa.Simple, legible y adecuado para notas o un valor por línea.Sin un convenio claro, los campos y tipos resultan ambiguos.
CSVFilas con campos delimitados, a menudo con cabecera.Natural para datos tabulares e intercambio con hojas de cálculo.Existen dialectos; no representa bien jerarquías y al leer entrega texto.
JSONObjetos, arrays y valores básicos anidados.Representa registros y jerarquías de forma interoperable.No admite directamente cualquier objeto de Python y no incluye comentarios estándar.

Texto plano: el programa define el convenio

Un fichero de texto puede contener una frase, un valor por línea o cualquier protocolo sencillo. Su simplicidad es una ventaja solo si quedan claras las reglas: qué significa cada línea, cómo se escapan separadores y cómo se representan datos ausentes. Para una tabla con varios campos es preferible usar el módulo csv en lugar de dividir manualmente por comas.

CSV: filas y columnas

CSV parece sencillo, pero un campo puede contener el delimitador, comillas o saltos de línea. El módulo estándar resuelve esas reglas y permite trabajar por posiciones con reader/writer o por cabeceras con DictReader/DictWriter. La documentación indica abrir los ficheros con newline="" para que el módulo gestione correctamente los finales de línea.[74]

import csv

with open("alumnos.csv", newline="", encoding="utf-8") as entrada:
    alumnos = list(csv.DictReader(entrada))

with open("seleccion.csv", "w", newline="", encoding="utf-8") as salida:
    escritor = csv.DictWriter(salida, fieldnames=["nombre", "nota"])
    escritor.writeheader()
    escritor.writerows(
        {"nombre": alumno["nombre"], "nota": alumno["nota"]}
        for alumno in alumnos
    )

Antes de escribir se proyecta cada registro sobre las dos columnas de salida. Así, una columna adicional del fichero de entrada —por ejemplo, grupo— no provoca un error ni aparece por accidente en seleccion.csv. Una clave obligatoria ausente sí debe tratarse como dato no válido. Al leer CSV, los campos se reciben normalmente como cadenas: que una columna se llame nota no la convierte en número, por lo que hay que validar y aplicar float o int cuando corresponda. El delimitador tampoco es siempre una coma; algunos ficheros utilizan punto y coma o tabulador.

JSON: datos estructurados

JSON representa objetos, arrays, cadenas, números, booleanos y null. Al cargarlo en Python, los objetos se convierten normalmente en diccionarios, los arrays en listas y null en None. json.load lee desde un fichero y json.dump escribe en él; las variantes loads y dumps trabajan con cadenas.[75]

import json

with open("alumnos.json", encoding="utf-8") as entrada:
    alumnos = json.load(entrada)

with open("salida.json", "w", encoding="utf-8") as salida:
    json.dump(alumnos, salida, ensure_ascii=False, indent=2)

ensure_ascii=False conserva letras como ñ de forma legible en un fichero UTF-8; indent=2 facilita la lectura humana a cambio de algunos bytes. Los conjuntos no son serializables directamente en JSON: antes hay que convertirlos, por ejemplo, en listas, y aceptar que JSON no conserva el significado de «conjunto».

Formato no equivale a contenido válidoUn documento puede ser JSON sintácticamente correcto y aun así carecer de las claves que necesita el programa. El analizador comprueba la sintaxis del formato; la aplicación debe comprobar el esquema y el significado.

7. Rutas, codificación y almacenamiento temporal en Google Colab

Rutas: localizar sin unir cadenas a mano

Una ruta indica dónde se encuentra un fichero dentro del sistema. Puede ser relativa al directorio de trabajo o absoluta desde la raíz. pathlib.Path representa rutas como objetos y permite unir componentes con /, comprobar existencia y crear carpetas de manera más legible que concatenando separadores manualmente.[76]

from pathlib import Path

carpeta = Path("datos")
carpeta.mkdir(exist_ok=True)
ruta_salida = carpeta / "resumen.json"
print(ruta_salida.resolve())

Una ruta relativa idéntica puede apuntar a lugares diferentes si cambia el directorio de trabajo. En Colab puede consultarse con Path.cwd(). Antes de leer, ruta.exists() ayuda a distinguir un fichero ausente de un error posterior de contenido, aunque entre la comprobación y la apertura el estado todavía podría cambiar.

Codificación: traducir entre texto y bytes

Un fichero almacena bytes; una cadena de Python contiene caracteres Unicode. La codificación establece la traducción. Python usa la codificación indicada en open; declararla como encoding="utf-8" hace el fichero más predecible entre entornos. El HOWTO oficial explica la diferencia entre puntos de código Unicode, cadenas y secuencias de bytes.[77]

Si un fichero fue guardado con otra codificación, abrirlo como UTF-8 puede producir UnicodeDecodeError o caracteres incorrectos. No se debe «arreglar» el problema eliminando tildes: hay que identificar la codificación de origen y convertir conscientemente. En modo binario no se indica encoding, porque el programa recibe y escribe bytes.

El disco de ejecución de Colab es temporal

Un cuaderno de Google Colab ejecuta código en una máquina virtual privada para la cuenta. Esa máquina se elimina tras un periodo de inactividad y tiene una vida máxima; por tanto, los ficheros guardados solo en el entorno de ejecución no deben considerarse persistentes. Colab también señala que los límites y tiempos pueden variar.[78]

Entorno de ejecución

Es apropiado para entradas y resultados temporales de la sesión. En los entornos alojados, el directorio habitual de trabajo es /content. Reiniciar, desconectar o reciclar la máquina puede borrar esos ficheros.

Almacenamiento persistente

El resultado que deba conservarse se descarga al equipo o se copia a un almacenamiento externo autorizado, como Google Drive. Montar Drive da al cuaderno acceso a los archivos del usuario y exige tratar permisos y datos sensibles con cuidado.

El cuaderno oficial de E/S de Colab muestra mecanismos para subir ficheros desde el navegador, descargar resultados y montar Google Drive.[79] Para entradas pequeñas puede usarse files.upload(); para entregar una salida, files.download(ruta). La subida debe realizarla una persona en la interfaz y el nombre recibido debe comprobarse, porque no siempre coincide con el que esperaba el programa.

from google.colab import files

subidos = files.upload()       # devuelve {nombre: bytes}
nombre = next(iter(subidos))
# ... procesar y crear "resumen.json" ...
files.download("resumen.json")
Temporal no significa copia de seguridadQue un fichero aparezca en el panel lateral de Colab solo confirma que existe en la sesión actual. Si importa conservarlo, debe exportarse antes de que termine el entorno y verificarse en su destino.

8. Carga, validación, transformación y exportación de datos

Un programa de datos fiable separa etapas. Así resulta más sencillo saber si un fallo procede del acceso al fichero, del formato, de un valor incorrecto o de la transformación. Las cuatro fases no exigen cuatro programas distintos, pero sí responsabilidades reconocibles.

1 — Carga

Localizar la entrada, abrirla con modo y codificación correctos y analizar su formato. El resultado es una colección de Python todavía no confiable.

2 — Validación

Comprobar estructura, campos obligatorios, tipos, rangos y reglas del problema. Registrar o comunicar los datos rechazados sin mezclarlos silenciosamente con los válidos.

3 — Transformación

Convertir tipos, normalizar textos, filtrar, ordenar, agrupar o calcular agregados. La transformación trabaja sobre una representación ya comprobada.

4 — Exportación

Elegir formato y ruta según el destinatario, escribir sin destruir el original y volver a abrir o inspeccionar el resultado para confirmar que se puede utilizar.

Carga: conservar el origen

La carga debe distinguir entre «no se encontró el fichero» y «se encontró, pero su contenido no cumple el formato». También conviene conservar el fichero original sin modificar. Limpiar directamente la única copia impide revisar qué llegó realmente y repetir el proceso con reglas mejores.

Validación: forma, tipo y significado

Validar no consiste solo en capturar cualquier excepción. Primero se comprueba la estructura —por ejemplo, que JSON contenga una lista—; después cada registro y sus claves; a continuación se convierten tipos; por último se aplican reglas de significado, como que una nota esté entre 0 y 10.

def convertir_registro(fila):
    nombre = fila.get("nombre", "").strip()
    nota = float(fila["nota"])
    if not nombre or not 0 <= nota <= 10:
        raise ValueError("registro no válido")
    return {"nombre": nombre, "nota": nota}

La función devuelve un registro nuevo y uniforme o señala que no puede construirlo. El programa que la llama decide si detiene todo el proceso o conserva una relación de filas rechazadas. Sustituir cualquier valor defectuoso por cero sin avisar sería peligroso: convertiría «desconocido» en una medida real.

Transformación: una decisión reproducible

Las reglas deben producir el mismo resultado al ejecutarse otra vez sobre el mismo origen. Separar datos originales y datos transformados facilita esa reproducibilidad. Los nombres de las variables pueden reflejar las etapas:

validos = [convertir_registro(fila) for fila in filas]
aprobados = [r for r in validos if r["nota"] >= 5]
ordenados = sorted(aprobados, key=lambda r: r["nota"], reverse=True)
media = sum(r["nota"] for r in validos) / len(validos) if validos else None

En datos pequeños, crear colecciones nuevas mejora la legibilidad y conserva estados intermedios. En conjuntos grandes puede ser necesario procesar línea a línea, pero el principio se mantiene: cada etapa recibe una entrada definida y produce una salida comprobable.

Exportación: adaptar y comprobar

La salida se elige según quién la utilizará. CSV resulta cómodo para una tabla; JSON conserva mejor una estructura anidada; texto plano sirve para un informe muy sencillo. Antes de escribir hay que decidir cabeceras, orden, valores ausentes, separador, codificación y si se reemplaza un fichero existente. Después se comprueba el archivo real, no solo la colección que había en memoria.

  1. Escribir en una ruta de salida distinta de la entrada.
  2. Confirmar que el fichero existe y tiene el formato esperado.
  3. Volver a cargarlo con el lector correspondiente.
  4. Comparar número de registros y campos esenciales.
  5. En Colab, descargarlo o copiarlo al destino persistente y abrir esa copia.
Flujo completoEntrada original → carga según el formato → validación de estructura y valores → transformación explícita → exportación a una ruta nueva → recarga y verificación → conservación fuera del almacenamiento temporal.

Glosario del tema

Colección
Estructura que reúne varios valores y define cómo se organizan y consultan.
Mutable
Objeto cuyo contenido puede cambiar sin crear otro objeto.
Inmutable
Objeto cuyo valor no puede modificarse después de su creación.
Índice
Posición numérica de un elemento dentro de una secuencia.
Clave
Identificador único que permite acceder a un valor de un diccionario.
Iterable
Objeto cuyos elementos se pueden recorrer uno tras otro.
Filtrado
Selección de los elementos que cumplen una condición.
Agregación
Cálculo que resume varios datos, como una suma, un recuento o una media.
Registro
Conjunto de campos relacionados que describen una entidad u observación.
Estructura anidada
Colección que contiene otras colecciones.
Gestor de contexto
Mecanismo usado por with para preparar un recurso y liberarlo al salir del bloque.
Serialización
Conversión de una estructura de datos a una representación almacenable o intercambiable.
CSV
Familia de formatos tabulares que representa registros mediante campos delimitados.
JSON
Formato textual de intercambio basado en objetos, arrays y valores simples.
Ruta relativa
Localización interpretada desde el directorio de trabajo actual.
Codificación
Regla que relaciona caracteres de texto con secuencias de bytes.
Persistencia
Conservación de datos más allá de la ejecución o sesión que los produjo.
Validación
Comprobación de que la estructura, los tipos y los valores cumplen reglas definidas.

Resumen esencial

  1. Las listas son secuencias mutables; las tuplas, secuencias inmutables; los diccionarios asocian claves con valores; los conjuntos conservan elementos únicos.
  2. Acceder, modificar, recorrer, buscar, ordenar, filtrar y agregar son operaciones distintas que deben expresar una intención clara.
  3. sort modifica una lista; sorted produce una nueva. Una comprensión puede filtrar o transformar si permanece legible.
  4. Las estructuras anidadas representan registros y tablas sencillas, pero deben mantener campos y tipos coherentes.
  5. La colección se elige según orden, duplicados, mutabilidad, forma de acceso y operaciones necesarias.
  6. with open(...) delimita el uso del fichero y asegura su cierre; el modo de apertura determina si se lee, añade o reemplaza contenido.
  7. Texto plano requiere un convenio; CSV representa tablas; JSON representa estructuras anidadas con tipos básicos.
  8. Las rutas deben construirse de forma portable y el texto debe abrirse con una codificación explícita, normalmente UTF-8.
  9. El almacenamiento del entorno de ejecución de Colab es temporal; una salida importante debe descargarse o copiarse y verificarse fuera de la sesión.
  10. Un flujo fiable separa carga, validación, transformación y exportación, conserva el original y vuelve a comprobar el fichero producido.
