Clases y objetos: modelar un problema

Cómo reunir datos y operaciones en modelos sencillos, crear entidades con estados independientes y hacer que colaboren sin convertir el programa en una maraña de variables.

Pregunta guía

¿Cuándo deja de bastar una colección de datos y resulta útil representar cada entidad del problema como un objeto responsable de su propio estado?

Programar también consiste en decidir cómo representar la realidad que importa para una solución. En este tema seguiremos la historia de una pequeña biblioteca: primero describiremos libros con datos sueltos; después construiremos objetos que saben prestar y devolver ejemplares; finalmente los reuniremos en un catálogo que puede colaborar con funciones y ficheros. El recorrido desarrolla la introducción a clases, objetos y organización modular prevista en el currículo.[80]

Antes de empezar: una ficha de un libro contiene datos; una biblioteca, además, necesita mantener reglas. No basta con recordar si un ejemplar está prestado: también hay que impedir que se preste dos veces y conservar una organización comprensible cuando hay muchos ejemplares.
Al terminar serás capaz de…
  • distinguir clase, objeto, instancia, atributo y método;
  • definir una clase sencilla y explicar el papel de __init__ y self;
  • crear varias instancias con estados independientes;
  • relacionar estado, comportamiento y reglas de consistencia;
  • aplicar encapsulación básica y elegir composición para construir modelos;
  • manejar colecciones de objetos y conectarlas con funciones y ficheros;
  • decidir entre diccionarios, funciones y clases según el problema;
  • describir una organización modular sencilla sin perder de vista el conjunto.

1. Clase, objeto, instancia, atributo y método

Una clase define una clase de entidades: indica qué datos guardan y qué operaciones pueden realizar. Un objeto es una entidad concreta creada a partir de esa definición. Por eso también se dice que es una instancia de la clase. En Python, las clases permiten agrupar datos y funcionalidad, y cada instancia puede mantener su propio estado.[81]

La ficha y el ejemplar

La clase se parece al diseño de una ficha bibliográfica: establece que habrá un título, una autoría y un estado de préstamo. Un objeto es una ficha ya cumplimentada para un ejemplar concreto.

El plano y la casa

Un mismo plano puede guiar la construcción de muchas casas. Comparten estructura, pero cada casa tiene dirección, habitantes y estado propios. Del mismo modo, varias instancias comparten clase sin compartir necesariamente sus datos.

Vocabulario básico aplicado a una biblioteca
ConceptoQué representaEjemplo

En Python, todo objeto tiene una identidad, un tipo y un valor; el estado que nos interesa forma parte de ese valor y puede cambiar si el objeto es mutable.[82] En nuestro modelo no intentaremos copiar una biblioteca real con todos sus detalles: elegiremos únicamente lo necesario para resolver el problema.

Modelar es seleccionarUn modelo no es la realidad completa. Si la aplicación solo gestiona préstamos, quizá necesite título, identificador y disponibilidad, pero no el color de la cubierta. Cada atributo debe justificar su presencia por alguna decisión del programa.

2. Definición de clases, __init__ y self

Una clase se define con la palabra class. Dentro se escriben métodos. El método especial __init__ se ejecuta después de crear una instancia y sirve para dejarla en un estado inicial válido. Python pasa la nueva instancia como primer argumento; por convención ese parámetro se llama self.[81]

class Libro:
    def __init__(self, titulo, autoria):
        self.titulo = titulo
        self.autoria = autoria
        self.prestado = False

    def descripcion(self):
        return f"{self.titulo}, de {self.autoria}"

La asignación self.titulo = titulo reúne dos elementos con nombres parecidos pero funciones distintas. El titulo de la derecha es el argumento recibido; self.titulo es el atributo que quedará guardado en esa instancia. self no es una palabra reservada, pero usar ese nombre hace que el código sea reconocible para otras personas.

class Libro

Crea una nueva clase llamada Libro. Los nombres de clases suelen escribirse con inicial mayúscula.

__init__

Recibe los datos iniciales y establece atributos. No «fabrica» por sí solo el objeto: inicializa la instancia recién creada.

self

Permite que el método consulte o cambie la instancia concreta que recibió la llamada.

Método

Se define como una función dentro de la clase. Al llamar libro.descripcion(), Python vincula libro con self.

Los dobles guiones bajos de nombres como __init__ indican métodos especiales con un significado definido por el modelo de datos de Python. No conviene inventar nombres propios con esa forma.[83]

Evita atributos compartidos por accidenteLos datos que deben pertenecer a cada ejemplar se asignan normalmente a self dentro de __init__. Colocar una lista mutable directamente en el cuerpo de la clase podría hacer que todas las instancias compartieran la misma lista.

3. Creación y uso de varias instancias

Llamar a la clase crea una instancia. Cada llamada puede recibir datos distintos y produce un objeto con identidad propia. Los nombres de variables solo nos permiten referirnos a esos objetos.

libro_1 = Libro("Frankenstein", "Mary Shelley")
libro_2 = Libro("Nada", "Carmen Laforet")

print(libro_1.descripcion())
print(libro_2.descripcion())

Ambos objetos entienden el método descripcion porque comparten la clase Libro, pero sus atributos contienen valores diferentes. Cambiar el estado de uno no debería alterar el otro:

libro_1.prestado = True

print(libro_1.prestado)  # True
print(libro_2.prestado)  # False
Variables y objetos no son lo mismo. Una variable contiene una referencia a un objeto. Si hacemos favorito = libro_1, no se crea otro libro: ambos nombres se refieren a la misma instancia. Un cambio observado a través de uno también se verá a través del otro.

Comparar objetos también exige intención. is pregunta si dos referencias señalan exactamente al mismo objeto; == pregunta si se consideran iguales. En una clase sencilla que no define una regla especial de igualdad, dos instancias con los mismos títulos pueden seguir siendo objetos distintos.[82]

Tres situaciones que no conviene confundir

4. Estado, comportamiento y reglas básicas de consistencia

El estado es el conjunto de datos relevantes que un objeto mantiene en un momento dado. El comportamiento son las operaciones que puede realizar. En un buen modelo, los métodos expresan acciones del dominio y protegen sus reglas: un libro disponible puede prestarse; uno ya prestado no debe volver a prestarse.

class Libro:
    def __init__(self, titulo, autoria):
        self.titulo = titulo
        self.autoria = autoria
        self.prestado = False

    def prestar(self):
        if self.prestado:
            return False
        self.prestado = True
        return True

    def devolver(self):
        self.prestado = False

La regla está cerca del dato que protege. En lugar de repartir asignaciones como libro.prestado = True por todo el programa, las demás partes solicitan libro.prestar(). El valor de retorno informa de si la transición pudo realizarse.

Estado inicial — disponible

prestado vale False al terminar __init__.

Acción — prestar

El método comprueba la regla. Si el libro está disponible, cambia su estado y comunica éxito.

Estado posterior — prestado

Una segunda petición no altera el objeto y comunica que la operación no era válida.

Acción — devolver

El objeto vuelve a quedar disponible para otra operación.

Una regla de consistencia o invariante expresa algo que debe seguir siendo cierto durante la vida del objeto. Por ejemplo, si se modelara un número de copias, no debería ser negativo. __init__ establece un punto de partida coherente y los métodos preservan las reglas al cambiar el estado.

Idea de diseño: un objeto no es solo una bolsa de atributos con una etiqueta. Su valor aparece cuando reúne el estado con las operaciones que tienen sentido y evita transiciones imposibles o contradictorias.

5. Encapsulación y composición a nivel introductorio

Encapsular para reducir dependencias

Encapsular consiste en reunir una responsabilidad y ofrecer una forma clara de usarla sin obligar al resto del programa a conocer cada detalle interno. Python no impone privacidad absoluta: un nombre que empieza por un guion bajo, como _libros, comunica que es un detalle interno y no debería manipularse desde fuera, aunque el lenguaje permita acceder a él.[84]

La encapsulación introductoria se apoya más en acuerdos y métodos bien elegidos que en barreras. La biblioteca podrá ofrecer añadir y buscar; quien la use no necesita recorrer o modificar directamente su almacenamiento interno.

Componer: construir un objeto con otros objetos

La composición expresa una relación «tiene»: una Biblioteca tiene una colección de objetos Libro. Cada clase mantiene una responsabilidad: Libro controla el estado de un ejemplar y Biblioteca organiza varios ejemplares.

class Biblioteca:
    def __init__(self, nombre):
        self.nombre = nombre
        self._libros = []

    def añadir(self, libro):
        self._libros.append(libro)

    def disponibles(self):
        return [libro for libro in self._libros
                if not libro.prestado]
biblioteca = Biblioteca("Biblioteca del instituto")
biblioteca.añadir(libro_1)
biblioteca.añadir(libro_2)
La composición es el centro de este temaUna aplicación se entiende mejor cuando colaboran piezas pequeñas: la biblioteca no hereda de libro ni el libro hereda de biblioteca. La primera contiene libros y les pide que realicen sus propias operaciones.
Reparto de responsabilidades mediante composición
ObjetoSabeHaceNo debería decidir
LibroSu título, autoría y disponibilidad.Prestarse y devolverse sin romper sus reglas.Cómo se guardan todos los libros en un fichero.
BibliotecaSu nombre y qué libros contiene.Añadir, localizar y seleccionar libros.Cómo se presenta un menú o se pregunta al usuario.
Interfaz o función externaQué información necesita mostrar.Recibir entrada y presentar resultados.Modificar atributos internos saltándose los métodos.
Ampliación no obligatoria: la herencia permite definir una clase a partir de otra y el polimorfismo permite tratar de forma común objetos con comportamientos compatibles. Son ideas útiles, pero no se exigen en este tema: para el modelo de la biblioteca priorizamos composición y responsabilidades claras.

6. Colecciones de objetos y colaboración con funciones y ficheros

Los objetos no sustituyen a las colecciones: colaboran con ellas. Una lista puede contener objetos Libro, y los recorridos, filtros y búsquedas aprendidos anteriormente siguen siendo válidos. La diferencia es que cada elemento reúne ahora sus datos con su comportamiento.

def buscar_por_titulo(libros, texto):
    texto = texto.casefold()
    return [libro for libro in libros
            if texto in libro.titulo.casefold()]

Esta función no necesita convertirse en método si resulta útil con cualquier colección de libros y no modifica el interior de una biblioteca. Las clases y las funciones no compiten: una clase concentra responsabilidades ligadas a una entidad; una función puede coordinar datos, transformar una colección o separar entrada y presentación.

Guardar datos, no objetos «mágicamente»

Para conservar el catálogo en JSON, primero se traduce cada objeto a tipos que el formato conoce: diccionarios, listas, cadenas, números, booleanos y valores nulos. El módulo json serializa esos tipos básicos, pero un objeto Libro necesita una conversión explícita.[85]

def libro_a_dict(libro):
    return {
        "titulo": libro.titulo,
        "autoria": libro.autoria,
        "prestado": libro.prestado,
    }


def libro_desde_dict(datos):
    libro = Libro(datos["titulo"], datos["autoria"])
    prestado = datos.get("prestado", False)
    if not isinstance(prestado, bool):
        raise ValueError("El estado 'prestado' debe ser booleano")
    if prestado:
        libro.prestar()
    return libro

La escritura y la lectura quedan en funciones de frontera. Así, Libro no necesita saber en qué carpeta vive el archivo ni cómo funciona JSON:

import json


def guardar_catalogo(ruta, libros):
    datos = [libro_a_dict(libro) for libro in libros]
    with open(ruta, "w", encoding="utf-8") as fichero:
        json.dump(datos, fichero, ensure_ascii=False, indent=2)


def cargar_catalogo(ruta):
    with open(ruta, encoding="utf-8") as fichero:
        datos = json.load(fichero)
    return [libro_desde_dict(dato) for dato in datos]

El gestor de contexto with asegura el cierre del fichero al terminar el bloque, incluso si ocurre un error durante el trabajo con él.[86] Al cargar, los datos externos deben validarse antes de aceptarse como estado del programa: un fichero puede estar incompleto, tener tipos inesperados o haber sido modificado.

JSON no conserva métodosEl fichero guarda una representación de los datos, no el comportamiento de la clase. Al cargarlo, el programa reconstruye nuevas instancias de Libro usando el código actual de la aplicación.

7. Comparación entre diccionarios, funciones y clases

Una clase no es automáticamente la mejor solución. Para dos valores que solo se muestran una vez, un diccionario puede ser más claro. Si una transformación no necesita mantener estado, una función suele bastar. Las clases ganan sentido cuando aparecen muchas entidades del mismo tipo, estados que cambian y reglas que deben aplicarse de forma coherente.

Tres maneras de organizar una solución
RecursoResulta adecuado cuando…Ventaja principalSeñal de límite
DiccionarioHay un registro de datos sencillo, flexible o destinado a intercambio.Representación directa mediante claves y valores; encaja bien con JSON.[87]Las mismas reglas y operaciones se repiten alrededor de muchos diccionarios.
FunciónSe transforma una entrada en una salida o se coordina una tarea concreta.Responsabilidad breve, explícita y fácil de reutilizar.Necesita recibir y devolver continuamente un grupo creciente de datos relacionados.
ClaseMuchas entidades comparten estructura y comportamiento, mantienen estado y deben respetar reglas.Une datos y métodos bajo un vocabulario del problema.Solo agrupa funciones sin estado o añade capas que no aclaran la solución.

La misma acción, dos enfoques

Diccionario más función

libro = {
    "titulo": "Nada",
    "prestado": False
}

def prestar(datos):
    if datos["prestado"]:
        return False
    datos["prestado"] = True
    return True

Objeto con método

libro = Libro(
    "Nada",
    "Carmen Laforet"
)

exito = libro.prestar()

Las dos versiones pueden funcionar. La primera es razonable para datos sencillos; la segunda da un nombre al tipo de entidad y coloca la regla junto a su estado. La decisión se toma por claridad y necesidades del problema, no por el deseo de usar la técnica más nueva.

Criterio práctico: empieza con la representación más sencilla que mantenga el programa claro. Considera una clase cuando puedas nombrar una entidad, describir su estado, identificar comportamientos propios y formular reglas que deban cumplirse en todas sus instancias.

8. Organización modular de una aplicación sencilla

Una aplicación es modular cuando se divide en partes con responsabilidades comprensibles y relaciones explícitas. Un módulo de Python es un archivo que contiene definiciones y sentencias; otros módulos pueden reutilizar sus nombres mediante import.[88] En este tema importa primero la organización conceptual: aunque todo se escriba inicialmente en un cuaderno o un solo archivo, conviene reconocer las capas.

Modelo

Libro y Biblioteca: representan entidades, mantienen estado y protegen reglas.

Persistencia

guardar_catalogo y cargar_catalogo: traducen entre objetos y datos del fichero.

Aplicación

Coordina el caso de uso: pedir una búsqueda, solicitar un préstamo y comunicar el resultado.

Presentación

Se ocupa de entradas y salidas. No debería contener las reglas que determinan si un préstamo es válido.

1 — Cargar

La frontera de persistencia lee el fichero, valida sus datos y reconstruye objetos.

2 — Coordinar

La aplicación localiza el libro solicitado y pide al objeto que realice la operación.

3 — Proteger reglas

El modelo acepta o rechaza el préstamo según su estado, sin depender de cómo se mostrará el resultado.

4 — Presentar y guardar

La interfaz comunica el resultado y la persistencia conserva el nuevo estado.

Ampliación no obligatoria: si la aplicación creciera, estas responsabilidades podrían separarse en archivos como modelos.py, persistencia.py y app.py. En el trabajo obligatorio basta reconocer y aplicar la organización conceptual dentro de un cuaderno o un solo archivo. Dividir sin criterio puede esconder el recorrido de los datos y complicar un programa pequeño.
Una historia completaLos datos entran desde un fichero, se convierten en objetos, colaboran dentro de una colección, cambian mediante métodos que preservan reglas y vuelven a una representación guardable. La modularidad consiste en que cada parte conozca lo necesario, no en multiplicar archivos.

Resumen esencial

  1. Una clase define estructura y comportamiento; un objeto es una instancia concreta con identidad y estado propios.
  2. Los atributos guardan datos y los métodos expresan operaciones relacionadas con la entidad.
  3. __init__ deja cada nueva instancia en un estado inicial y self identifica la instancia sobre la que actúa un método.
  4. Varias instancias comparten definición, pero mantienen estados independientes; dos nombres también pueden señalar el mismo objeto.
  5. Los métodos deben preservar reglas de consistencia al cambiar el estado.
  6. La encapsulación reduce dependencias; en Python se apoya en interfaces claras y convenciones como el guion bajo inicial.
  7. La composición modela relaciones «tiene» y permite repartir responsabilidades entre objetos pequeños que colaboran.
  8. Las colecciones pueden contener objetos; las funciones siguen siendo útiles para coordinar, transformar, presentar y gestionar ficheros.
  9. JSON conserva datos básicos, no métodos: al cargar se validan los datos y se reconstruyen instancias.
  10. Diccionarios, funciones y clases son opciones complementarias; se elige la solución más sencilla que mantenga claros el estado y las reglas.
  11. Una organización modular separa conceptualmente modelo, persistencia, aplicación y presentación antes de decidir cuántos archivos necesita.
  12. Herencia y polimorfismo quedan como ampliación no obligatoria; el núcleo introductorio es modelar mediante composición.
